# Astra 0.2.0 — workspaces and local commands

The second Linux alpha adds usable organization and conservative memory
management to the initial browser foundation. It is not the final release.

- Named workspaces separate website cookies/storage, with encrypted tab
  membership and shared local bookmarks/history.
- Ctrl/Cmd+K searches tabs, workspaces, history, bookmarks and actual commands
  locally. Typing does not contact a suggestion service.
- Tabs reorder by dragging or Alt+Shift+arrow keys. Order survives vault restart.
- Ctrl/Cmd+B collapses the sidebar to a narrow tab rail; the setting is saved
  with encrypted records.
- Background pages beyond the configured limit hibernate, with draft/audio
  safeguards, beforeunload protection and navigation/scroll restoration.
- “Behind the page” reports actual request/block counts and renderer-process
  memory. The memory figure may cover shared pages; it is not a per-tab total.
- Native Stay/Leave protects explicit navigation and closure. Address identity
  remains tied to committed documents when navigation is stopped or cancelled.
- Packaged resources now include Astra and Doto font license notices.

See [keyboard controls](../keyboard.md) and [architecture decisions](../decisions.md).

## Verification and limits

Source verification passes 19 unit tests, 11 real Electron integration tests
and the native lifecycle suite. Linux CI is active on every work branch and
main. Packaged runtime tests check rendering, page isolation, command execution
and notices. One initial packaged command-bar timeout did not reproduce in
six subsequent fresh-profile runs; failure-state diagnostics are retained.
Direct AppImage execution also passes the same rendering/isolation/command
checks with Chromium's sandbox enabled. A separate live HTTPS smoke check
rendered example.com successfully. Both published package hashes were checked
against the generated manifest before upload.

Website logins are still memory-only and clear on quitting. The bundled tracker
list is small, sensitive permissions are denied by default, and hibernation
reloads a page rather than serializing its running JavaScript heap. A secure OS
key store or explicit passphrase is required for persistent browsing records.
No telemetry, updater, cloud service or AI request runs in the background.

Split view, extensions, per-site customization, link previews, optional AI and
native Windows/macOS packages are not included yet. Screen-reader operation and
broad website compatibility still need manual verification. Debian archive
structure is inspected, but installation on Debian/Ubuntu has not been tested.
This remains an early alpha, not a hardened replacement for a mature browser.

## Linux x64 artifacts

- `Astra-0.2.0.AppImage`: mark executable and launch.
- `astra-browser_0.2.0_amd64.deb`: install using your Debian/Ubuntu package manager.
- `SHA256SUMS-0.2.0`: verify downloads with `sha256sum -c SHA256SUMS-0.2.0` in the
  directory containing both packages.

Close Astra before changing package versions. Existing passphrase vaults keep
their format; unlock them as before. Missing/corrupt keys are never replaced
automatically. Retain a backup of your vault directory before testing alphas.
