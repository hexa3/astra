# Contributing to Astra

Thank you for helping build a browser its users can inspect and replace.

## Start here

1. Search existing issues and RFCs.
2. For an ordinary fix, open an issue or pull request with a focused change.
3. For architecture, policy, compatibility, data-handling, funding, or governance changes, open an RFC using the issue form and add a numbered proposal based on `governance/rfcs/0000-template.md`.
4. Run `npm run verify` before requesting review. Explain any platform check you could not run.

Every interactive control needs a keyboard path and accessible name. Network and storage behavior must be disclosed. Do not add telemetry, advertising, silent remote calls, fake metrics, placeholder controls, or proprietary web APIs. Add architectural rationale to `docs/decisions.md` and user-visible changes to `CHANGELOG.md`.

Contributions are made under MPL 2.0. Add `SPDX-License-Identifier: MPL-2.0` in a comment supported by a new source file's format; the root license applies to formats such as JSON that do not support comments. Do not submit code you cannot license.

## Review and conduct

Review evaluates behavior, tests, security, privacy, accessibility, standards compatibility, and maintainability—not employer or status. Be specific, assume good faith, criticize work rather than people, and protect private vulnerability and personal information. Harassment, threats, discrimination, and retaliation are not accepted. Report sensitive conduct matters privately to the current maintainers; outcomes follow the transparent-with-necessary-redaction rule in `GOVERNANCE.md`.

Governance roles, voting, appeals, conflicts, and maintainer eligibility are defined in `GOVERNANCE.md`.
